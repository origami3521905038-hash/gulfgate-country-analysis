# 决策级报告设计

本规范用于市场进入、营销方案、组织/行政体系、投资可行性、建厂与本地化、跨国比较、多年规划等复杂任务。目标不是单纯写长，而是让管理者能够据此选择路径、配置资源、安排下一步验证。

## 一、先决定交付层级

按决策复杂度选择，不按用户问题字数选择：

- **直接答复**：术语、单点事实、一个局部判断；通常 300–700 中文字。
- **决策简报**：一个明确决策、2–4 个关键变量、短期动作；通常 1200–2500 字。
- **完整报告**：涉及多个模块、多个阶段或重大资源投入；例如市场进入、营销体系、组织搭建、建厂、本地化、三年规划；通常 2500–6000 字，材料充分时可更长。

用户要求“报告、方案、规划、路线图、可行性、全面分析”或问题天然跨市场/准入/渠道/交付/财务等模块时，默认使用完整报告。用户明确要简短时压缩表达，但保留决定性条件、关键数字和行动路径。

## 二、建立分析主线

完整报告先在内部写出一句决策问题，例如：“是否以及以何种路径进入某国某细分市场，并在什么条件下升级投入。”随后只保留能服务这个决策的模块。

每个核心结论都应能沿以下链条回溯：

**事实或输入 → 机制/计算/比较 → 对业务的影响 → 建议动作 → 触发或停止条件**

不要把国家概况、政策、文化、渠道和风险各写一段后留给用户自行拼接。必须说明这些因素怎样共同改变市场选择、进入顺序、预算、人员或承诺。

复杂任务通常要回答五类问题：

1. 机会是否存在，具体落在哪个客户、用途、地区或场景，而不是只说宏观市场大。
2. 企业通过什么交易和交付路径取得收入，关键角色分别是谁。
3. 准入、资源、成本和运营条件能否支撑这条路径。
4. 先做什么、后做什么；什么结果出现后升级投入，什么结果出现时停止或改道。
5. 管理层怎样持续监控：关键指标、责任角色、复盘节奏和高风险前置项。

## 三、完整报告的推荐骨架

以下是模块库，不是固定目录。按任务删减、合并和改名；不要为了齐全写与决策无关的章节。

1. **标题与报告口径**：对象、国家/法域、产品/业务、时间基点、货币和关键范围。
2. **基础目录**：决策简报和完整报告在正文前列出实际使用的一级章节，并用短句说明每章回答的问题。Markdown 不虚构页码。
3. **执行摘要**：直接给出有方向性的结论；包含推荐路径、核心依据、最大约束、关键数字或区间，以及改变建议的条件。可以是一段，也可以是少量要点，不固定条数。
4. **业务场景与关键假设**：企业角色、产品用途、客户类型、进入阶段、时间/预算约束；将未确认但用于计算的内容明确标为假设。
5. **市场与需求**：需求驱动、可服务市场、客户/项目结构、采购机制、竞争和可达性；宏观规模只作为背景。
6. **准入与落地结构**：产品、企业、人员、项目各层要求；本地实体、代理、进口、安装、售后等责任边界。
7. **商业模式或方案选择**：比较 2–4 条现实路径，写清适用条件、优势、代价、失败点和推荐顺序。
8. **经济与资源模型**：价格/成本/预算/人员/现金流或产能模型；至少给基准情景，重要不确定性给保守—基准—乐观或敏感性分析。
9. **执行系统**：按阶段列目标、动作、负责人或建议责任角色、里程碑、前置条件和交付物。
10. **运营节奏与 KPI**：说明周/月/季度要看什么，指标如何触发加码、修正或退出。
11. **风险与验证计划**：按影响和可逆性排序；列验证对象、材料/访谈、完成标准、时点及未验证的后果。
12. **依据、假设与局限**：列关键来源，区分本次外部核验、用户材料、内部知识和分析推断；不把泛泛免责声明当结论边界。

## 四、按任务选择分析模块

### 市场进入或建厂/本地化

至少考虑：需求落点、买方与采购链、竞争、准入、进入路径、渠道/伙伴、售后与交付、单位经济、资本开支或固定成本、产能利用、阶段门槛、本地化收益与退出条件。

“是否建厂”不能只用市场规模回答。比较进口销售、代理分销、本地组装、合同制造、自建产线等路径；把订单稳定性、关税/本地价值、服务时效、核心部件来源、最低经济产量和可逆性放在同一框架中。

### 营销与增长方案

至少考虑：目标细分和决策单位、购买触发、价值主张、渠道漏斗、内容与信任机制、销售承接、预算分配、CAC/LTV/转化口径、实验设计、节日或季节节奏、数据归因和合规边界。

不要直接照搬通用平台数据到具体产品。渠道基准应说明适用范围；高客单价 B2B、安装型产品和快消品的漏斗不可混用。

### 组织、人力或行政体系规划

至少考虑：业务规模假设、实体与组织架构、法定与运营要求、人员数量与能力、数字平台/流程、薪酬福利与总成本、办公/供应商安排、年度合规节奏、阶段性组织演进、KPI 和风险控制。

路线图必须让人员规模、合规门槛、系统上线、预算和责任人相互对应，不能只列愿景。

### 多国或多方案比较

先建立同一比较口径；将硬门槛、商业吸引力、资源匹配、验证成本和可逆性分开。可以给推荐顺序，但分数和权重须有理由；证据不齐时不要用精确总分掩盖空白。

## 五、数字与模型规则

对每个影响结论的数字，内部标识其类型：

- **来源数字**：来自可引用材料；记录主体、时间、口径和适用范围。
- **用户输入**：由用户提供；注明“按用户提供/尚未独立核验”只在必要时出现。
- **计算结果**：展示公式或足以复算的过程，例如“单人年成本 × 人数”。
- **规划假设**：为做计划而设，不冒充市场事实；给验证方式或敏感性区间。

至少做到：统一币种与单位；标明基期；存量、流量、目标和预测不混写；市场规模、可服务市场、可获取收入不混写；比例变化同时检查绝对数量；价格、成本和收入说明是否含税、物流、服务或渠道分成。

没有可靠基准时，优先使用“计算框架 + 待填变量”或情景区间，不编造看似专业的精确数。若第三方估算差异大，展示区间和差异原因，不任选一个数字装成事实。

## 六、路线图与行动设计

阶段不能只有“短期/中期/长期”口号。每个阶段尽量包含：

| 要素 | 要回答的问题 |
|---|---|
| 目标 | 该阶段要消除哪项不确定性或建立哪种能力？ |
| 动作 | 具体做什么，向谁取得什么材料或完成什么交付？ |
| 建议责任角色 | 谁适合负责或确认？未获授权时不虚构具体负责人。 |
| 里程碑/KPI | 用什么可观察结果判断完成？ |
| 投入 | 预算、人力、合作方或系统需求是什么？ |
| 闸门 | 什么条件满足后进入下一阶段？什么情况暂停、退出或改道？ |

优先给 30/60/90 天、0–6/6–18/18+ 月或年度路线图中最适合任务的一种；时间段应由业务周期决定，不机械套模板。

## 七、来源呈现

关键主张就近引用直接来源。完整报告末尾可加简洁来源表，至少分清：

- 官方/监管/项目原始材料；
- 可靠市场或行业资料；
- 用户提供的内部材料；
- 计算与分析推断。

来源清单必须能追溯到实际材料。不要列未读取的文件，不以“语料库占比”代替主张级证据，也不要把多个转载视为独立证据。若报告主要基于历史知识库，应明确哪些关键项仍需本次核验。

## 八、交付前质量门槛

完整报告至少通过以下检查：

- 开头是否直接回答了“做不做、先做什么、在什么条件下升级”？
- 是否在正文前提供了与实际一级章节一致的基础目录，而不是套用固定目录？
- 是否至少有一条贯穿事实、判断、方案和行动的分析主线？
- 关键数字能否复算，假设与事实是否分开？
- 是否给出分阶段路线图、阶段闸门及可观察结果？
- 建议是否具体到对象、材料、角色、时点或完成条件？
- 是否同时呈现机会、约束与反向证据，而非单向论证？
- 来源是否真正支持对应主张，时效和适用范围是否匹配？
- 删除任何一节后若不影响决策，该节是否应删去或压缩？

质量不以标题数量、表格数量或字数衡量。优先补分析链和可执行性，再补背景信息。

## 九、从分析稿到可读成稿

上述模块用于检查内容是否完整，不是必须照抄的目录。分析完成后，读取[自然写作](natural-writing.md)，根据读者重新编排：把最影响选择的事实放到对应判断附近，把能连续解释的内容写成段落，只在真正需要比较或执行跟踪时使用表格。

尤其检查以下问题：

- 是否为了显得完整而设置过多章节、三级标题和对称列表；
- 是否用“战略含义、核心判断、证据包、抓手、闭环”等标签代替具体解释；
- 是否把同一个结论在摘要、国家分析、路线图和最终决策中重复四遍；
- 是否每个项目符号都加粗开头，或连续用相同句式；
- 是否把证据边界集中写成大段免责，而没有贴近具体主张；
- 是否出现大量“不是 X，而是 Y”式假对比、口号或行政元数据。

修订时保留独立信息，不为缩短而删掉条件、反证和来源。自然化不是把正式报告改成聊天，也不是刻意制造瑕疵；目标是让论证像一位熟悉业务的人在承担判断，而不是像模板在自动填栏目。
