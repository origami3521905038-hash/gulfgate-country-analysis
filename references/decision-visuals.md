# 决策图表规范

图表用于压缩判断时间：让管理者迅速看清差异、链条、约束、数字关系和投入条件。它不是装饰，也不能替代正文论证。

## 一、从决策问题选图

| 决策问题 | 首选表达 | 使用条件 |
|---|---|---|
| 国家、方案或进入路径怎样分工 | 对比矩阵、角色分工图 | 比较维度一致，差异会改变选择 |
| 收入、准入或交付经过哪些角色 | 采购链、责任链、利益相关方图 | 存在多个决策者、把关者或交付方 |
| 何时加码、暂停或退出 | 阶段闸门图、决策树 | 后续投入取决于可观察结果 |
| 数字差异有多大 | 比例条、区间表、折线或条形图 | 数字同口径、可追溯且可比较 |
| 哪个变量最改变结论 | 敏感性表、情景矩阵 | 模型可复算，变量关系明确 |
| 风险先处理什么 | 风险矩阵、优先级表 | 影响与可控性有统一口径 |

正文中的背景层级和重复结论不需要画图。两列表已经最清楚时，不改成流程图。

## 二、复杂报告的视觉检查

1. “选择图”：国家/方案对比、角色分工或推荐路径。
2. “落地图”：采购链、交易链、责任链或交付链。
3. “升级图”：路线图必须包含进入、暂停或退出条件。
4. 涉及市场规模、预算、成本、收入或产能时，提供可复算的数字图或情景表。

不是每份报告都机械包含四类，但跨国市场进入、建厂、本地化或多年规划若完全没有视觉表达，应重新检查。

## 三、单文件 Markdown 实现

最终报告只交付一个 `.md` 文件。所有视觉内容必须写入该文件：

1. 采购链、阶段闸门、组织关系和决策树优先使用 Mermaid `flowchart`。
2. 精确对比、负责人、KPI、风险和条件使用 Markdown 表格。
3. 有可靠可比数值时，可使用 Mermaid `xychart-beta`；若目标阅读器不稳定，则改用表格加 Unicode 比例条，确保纯文本仍可读。
4. 不创建外部 HTML、图片、图表数据文件或配套附件。不得引用本地绝对路径作为图表依赖。
5. Mermaid 节点文字保持简短，复杂解释放回正文；避免复杂交叉连线和实验性语法。

推荐的统一 Mermaid 主题如下，可在每张图开头直接嵌入：

```text
%%{init: {"theme":"base","themeVariables":{"primaryColor":"#E7F0EA","primaryTextColor":"#17362A","primaryBorderColor":"#5E7D70","lineColor":"#5E7D70","secondaryColor":"#F3E8D2","tertiaryColor":"#F7F4EC","fontFamily":"Microsoft YaHei, Noto Sans CJK SC, sans-serif"}}}%%
```

## 四、证据与口径

1. 图中的数字必须能识别为外部来源、用户输入、计算结果或规划假设。
2. 不同时间、币种、统计范围或产品口径不得直接并排造成可比错觉。
3. 规划目标不能画成已发生事实，企业自述不能画成行业事实。
4. 区间、不确定性和条件不能因制图而消失。图题或图下注明基期、单位、范围和主要假设。
5. 没有可靠数值时使用结构图、区间或待填模型，不虚构份额、分数、坐标或气泡大小。
6. 流程箭头只表达真实顺序、影响或依赖关系，不把相关性画成审批权或合同关系。

## 五、视觉体系

1. 一张图只承担一个主要结论，结论式标题写清对象与判断，不写“流程图”“战略图”。
2. 每张图保留四个部件：标题、单位/时间/图例说明、图形主体、来源与口径行。
3. 默认使用低饱和的深绿—砂金体系：深绿 `#17362A` 表示主结论，灰绿 `#5E7D70` 表示常规路径，砂金 `#C49A54` 表示关键条件，浅砂 `#F3E8D2` 和米白 `#F7F4EC` 用作背景。停止或高风险节点可少量使用暗红 `#9C4A3C`。
4. 同一报告不混用多套色系。去掉颜色后仍应依靠位置、长度、形状和标签读懂。
5. 不使用渐变、发光、玻璃拟态、三维效果或阴影。柱形长度与数值成比例，不使用断轴。
6. 地图只有在用户明确要求展示地域分布且数据确有地理意义时使用。

## 六、图文配合

图前或图后只需说明：图回答什么问题、应看到什么差异、该差异如何改变行动。不要逐节点复述。

图表的标题示例：

- “阿联酋与沙特在两年进入计划中的任务分工”
- “首个试点转为规模订单必须跨过的四道闸门”
- “渠道毛利变化对盈亏平衡销量的影响”

避免“生态、抓手、赋能、闭环”等抽象节点名称。若两张图得出同一结论，保留更清楚的一张。

## 七、交付前检查

1. 管理者能否从图中看出推荐顺序或关键条件？
2. 图是否减少理解成本，而不是把项目符号换成方框？
3. 节点、箭头、数字和正文是否一致？
4. 数字是否有单位、时间、口径和来源身份？
5. 阶段图是否有加码、暂停或退出条件？
6. 对比图是否使用同一维度？
7. 整份报告是否只使用一套色彩系统？
8. 删除该图是否会明显降低判断效率？若不会，删除。
