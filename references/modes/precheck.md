# 预检模式

用户将执行具体行动时使用。识别本次动作、时间、对象、权限、想达成的结果以及可能作出的承诺。行动不明时优先确认，不能给整个项目开通用“绿灯”。

围绕动作检查必要前提、已有材料、对方/内部确认、完成条件。可以开展探索性会谈而尚不能报价或签约；不同动作分别判断。授权、责任人、截止日未知时标待确认，建议角色不能冒充已指派人员。

将事项分为：推进前必须补齐、可并行处理、当前不影响本次动作。仅确有理由时列暂不宜承诺事项，解释补齐什么可以解除限制。未知不记通过或失败，不生成无依据准备率。

简报：本次动作与准备状态 → 关键缺口 → 可继续事项 → 暂不宜承诺 → 现场问题/材料清单与完成条件。

需要时用“检查项｜当前状态与依据｜缺失材料｜建议对接角色｜完成时点/条件”。日期只有用户或证据明确时才写具体值，否则写“报价前”等相对节点。不要机械把拜访清单扩大为整个市场进入的全部要求。

若预检对象是重大投标、设立实体、建厂、签署独家或启动多年计划，按风险和投入提高交付深度：除清单外，说明关键路径、前置依赖、资源/预算影响、责任角色、Go/No-Go 闸门和失败后的可逆方案。此时读取[决策级报告设计](../decision-grade-report.md)。
