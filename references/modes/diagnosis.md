# 诊断模式

用户给出判断或方案，要求检查合理性时使用。准确理解方案及用户目标；先承认已有证据支持的部分，再检查关键假设。不要为了输出“风险”而制造缺陷。

拆成：主张/动作、所依赖假设、已提供证据、反证/缺口、业务影响、修正动作。检查事实是否支持推理，责任和适用范围是否完整，是否遗漏成本、交付或回款条件。

状态区分：支持、附条件支持、尚不足判断、现有证据不支持。未提供资料不能写成没有能力/违法/不可行。条件已充分满足时明确肯定，避免重复索取。

简报：总体判断 → 成立部分 → 主要假设与问题 → 调整建议。需要时用“方案/假设｜证据｜判断｜影响｜修正”表格。仅检查相关主题，不强制七模块全覆盖。

修正建议优先沿用用户目标，在可行时提出小幅调整、补证或验证路径；不擅自替换项目目标。说明新证据如何改变结论。

若用户要求诊断完整市场方案、组织规划或投资计划，不能止于列风险。读取[决策级报告设计](../decision-grade-report.md)，补出修正后的推荐架构、关键模型、阶段路线图和验证闸门；原方案可保留的内容与需要重做的内容分别说明。
